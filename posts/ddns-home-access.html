给漂移的家宽装一个门牌

2026-11-26 · DDNS家庭网络 · 约 3 分钟

家里跑着几个小服务，我在外面也想敲得开。

家里跑着几个小服务，我在外面也想敲得开。

但家庭宽带有个尴尬的现实：运营商给的公网 IP 是漂的，隔三差五换一个。门牌号天天变，谁还找得到你家？

🐳 先看你有没有门

第一步不是装什么软件，而是确认这宽带到底有没有"真公网"。

办法很土：登录路由器看 WAN 口 IP，再搜一下本机出口 IP，两个对得上，就是真公网；对不上，说明你被运营商塞进了大内网（CGNAT），等于住在一个没有独立门牌的合租屋。

被塞进大内网也别慌，打运营商电话，说家里要装监控、要看 NAS，申请公网 IP 是合理需求，多数地区真能给。不给的话，还有 IPv6 这条路，家宽基本默认下发，只是要注意手机在外用流量时也得有 v6，双栈才稳。

🐳 让域名追着 IP 跑

有了会漂的公网 IP，剩下的问题就是：IP 变了，怎么让外面的人知道？

这就是 DDNS 干的事——定时检测自己的出口 IP，一变就更新 DNS 记录。核心逻辑几行就写完了：

last = ""
while True:
    ip = requests.get("https://api.ipify.org", timeout=5).text
    if ip != last:
        update("home", "example.com", ip)  # 调 DNS 服务商 API
        last = ip
    time.sleep(300)

当然，懒得写也没关系。现在不少路由器和 NAS 自带 DDNS 功能，填个密钥就行；也有现成的 Docker 镜像 ddns-go，Web 界面点几下，v4、v6 双栈通吃。我用的是定时任务加脚本，五分钟跑一次，够用了。

🐳 只开一扇门

门牌装好了，接下来是开门策略——这一步决定你会不会被扫。

我的原则很死板：路由器上只转发一条 443，所有服务收口到反向代理，统一走 HTTPS。路由器后台、NAS 管理页、SSH，一个端口都不往外放，想远程管理就回家再看（或者走之前写过的内网穿透那套）。

还有个绕不开的现实：不少地区运营商直接封了 80 和 443。对策要么换成 8443 这类高位端口，认了"域名:8443"这种不太优雅的访问形式，要么套一层 Cloudflare 回源。我选了前者，丑但能用。

💡 一点观察

折腾一圈下来，DDNS 本身反而是最简单的部分。难的从来是分清哪些门该开、哪些门必须焊死——网络这件事，最后的功夫都在收口上。
