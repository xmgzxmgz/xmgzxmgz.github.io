零依赖 Node 项目的取舍

2026-11-10 · Node.js 架构 · 约 2 分钟

一个带仪表盘、CI 和 Docker 的项目，package.json 里 dependencies 是空的。不是行为艺术，是部署环境的现实要求。

我的对话同步工具有个在别人看来有点偏执的设定：package.json 里 dependencies 是空的。整个项目——HTTP 服务、SQLite 存储、仪表盘、增量同步——只用 Node.js 标准库。

🤔 为什么

这个工具的目标部署环境是用户自己的 NAS 和家用服务器。这意味着：

  • npm install 拉下来的依赖树，用户没法逐个审计，但工具碰的是他们最私人的对话数据
  • NAS 上跑一个项目，为了它装几百个传递依赖，六个月后升级就是一场赌博
  • 依赖的安全公告会成为我的长期负债——每多一个依赖，就多一条「哪个版本有洞」的追踪义务

⚖️ 代价是真实的

轮子得自己造：路由、静态文件服务、参数校验、流式响应。有些地方标准库的 API 不如框架顺手。我的取舍标准是：这个项目五年后还要不要能一键跑起来？同步工具要的是十年不坏，不是三天搭完。

💡 什么时候不该这么做

原型、内部工具、生命周期以月计的东西——用框架，用最快的路。零依赖是一种和部署环境匹配的选择，不是美德。给一次性脚本上零依赖，是另一种过度设计。
