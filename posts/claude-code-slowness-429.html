Claude Code 变慢，先查这两处

2026-11-26 · Claude Code性能 · 约 2 分钟

AI 编程工具用久了变慢，多数人第一反应是「网络问题」或者「服务限流」。我做了一次完整诊断，发现真正的元凶在本地磁盘上——一个 2.3GB 的会话目录。

AI 编程工具用久了变慢，多数人第一反应是「网络问题」或者「服务限流」。我做了一次完整诊断，发现真正的元凶在本地磁盘上——一个 2.3GB 的会话目录。

🩺 排查清单怎么排

先查网络层：本地代理的健康检查端点五十毫秒返回，代理进程活着、端口正常监听；直连官方 API 延迟约一点四秒，有点高但不是瓶颈。排除网络，再查配置：全局规则文件一点五 KB，正常。

然后是真凶：主目录下的会话目录占了 2.3GB。其中一个会话文件 41MB，子代理目录 2.1GB、二百多个文件、最大的单个 64MB。这类工具启动和加载会话时要扫描这些文件，磁盘上一坨，响应上就是肉眼可见的卡顿。

处理也直接：清掉不再需要的旧会话，保留最近十到二十个，磁盘立刻回收 2GB 以上，启动速度明显回升。

🚦 429 不是故障

另一个高频误会：报 429 配额耗尽，很多人以为工具坏了。拆开看就两件事——429 是「请求太频繁」，配额耗尽是「这个计费周期的额度用完了」。不是网络问题，不是账号问题，是票用完了。

能做的就三件：等，多数按时段恢复；不够用就升档；或者省着点用——砍掉不必要的长上下文，别在循环里反复调用，大任务拆小。如果走的是自建网关和转发渠道，去确认那把钥匙的限额，别把锅甩给工具。

💡 一点观察

性能问题的排查顺序应该是「本地、网络、配额」：先看磁盘上的历史包袱，再量网络延迟，最后才怀疑远端服务。工具变慢的锅，十有八九在自己攒了半年的会话文件里。
