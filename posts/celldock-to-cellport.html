从 CellDock 到 CellPort

2026-09-20 · 硬件 对标 · 约 2 分钟

macOS 上有个 CellDock 管大疆 4G 模块，Windows 上什么都没有。对标实现的旅程里，最有价值的是列清楚「哪些我不做」。

这套大疆一代 4G 模块在 macOS 上有 CellDock，体验完整。Windows 上呢？串口助手，敲 AT 指令，仅此而已。CellPort 就是来填这个空的：短信、通话、设备信息、eSIM 切卡、AT 控制台，Windows 原生，不依赖 WSL。

🆚 对标过程中确认的三个差异

  1. EID 读不出来不一定是你的问题。SGP.22 和 SGP.02 两条路径在某些早期规范的卡上都被 ISD-R 拒绝（6A80 / 6D00）——是卡片不提供，CellDock 在同样的卡上一样读不到。Profile 管理不受影响
  2. 切卡后必须重启模块。modem 侧的 SIM 会话不会自动刷新，需要 AT+CFUN=1,1，约 40 秒。程序在写入成功后引导用户确认，然后自动重启、等端口恢复、重连、重读列表
  3. 数据拨号不归程序管。数据网卡由 Windows 自己处理，项目不介入——这条写在 README 里，省掉一类永远修不好的 issue

🚧 明确不做的

Profile 下载（ES10b + SM-DP+）暂缓：没有真实 SM-DP+ 服务器可联调之前，实现了也无法验证，宣称支持是不负责任的。Roadmap 里这条写着「待拿到可联调环境再落地」。

对标实现最容易翻车的地方不是功能少，是功能多出来还都是没法验证的。
