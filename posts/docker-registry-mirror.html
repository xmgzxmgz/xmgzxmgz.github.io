docker pull 卡住之后，我换了四条路

2026-11-26 · dockerNAS · 约 2 分钟

又是那个熟悉的画面：docker pull 走到一半，进度条不动了。等十分钟，超时。

镜像拉不下来，编排写得再漂亮也是纸上谈兵。折腾过几轮之后，我梳理出四条路，按救急程度排序。

🚑 加速源救急，不救命

第一反应都是配镜像加速源：daemon.json 里加一个 registry-mirrors 列表，重启 Docker，立刻见效。

但用了几个月我就发现，加速源的时效性很强，今天能用的源，下个月可能就慢得像没有。所以我的原则是：加速源只当救急手段，别死守一份列表，隔段时间拿个小镜像验证一下，不通就换。

🧭 更稳的一招：让 dockerd 走代理

如果你手上本来就有可用的代理，那更稳定的解法是给 Docker 守护进程整体配上出网代理，而不是逐个换源。Linux 下用 systemd 的 drop-in：

# /etc/systemd/system/docker.service.d/proxy.conf
[Service]
Environment="HTTP_PROXY=http://127.0.0.1:7890"
Environment="NO_PROXY=localhost,127.0.0.1"  # 内网网段按需补充

daemon-reload 再重启 Docker 就生效。好处是一次配置，所有拉取动作统一出网，不用操心哪个源又挂了。

🏭 多台机器，就自建一个仓库

家里设备一多，每台都配代理就烦了。我的做法是在内网起一个私有 registry：一台机器走代理拉镜像，转推到私仓，其余机器全从内网拉。

# 内网起一个私有仓库
docker run -d -p 5000:5000 --restart unless-stopped \
  -v /data/registry:/var/lib/registry registry:2
# 中转机拉到镜像后转推
docker tag nginx:1.27 内网地址:5000/nginx:1.27
docker push 内网地址:5000/nginx:1.27

两个小坑：私仓没配 TLS 时要在 insecure-registries 里声明，改完重启 Docker，容器会跟着重启，挑低峰期操作；另外 registry 长期跑会堆积旧层，定期做一次垃圾回收，别让它悄悄吃盘。

至于完全没网的环境，docker save 导出、docker load 导入，笨但永远管用。

💡 一点观察

拉镜像这件事的解法链，本质是从「依赖别人」走向「自己可控」。加速源靠别人的好心，代理靠出网通道，私仓靠自己的内网——越往下走越踏实。
