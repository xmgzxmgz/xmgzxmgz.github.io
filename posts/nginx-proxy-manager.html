不写配置文件的反代，能撑多久

2026-11-26 · Nginx反向代理 · 约 3 分钟

家里的服务越来越多，每个都得配一段反代加证书，手写配置文件写得我开始怀疑人生。

于是我把 Nginx Proxy Manager 请了出来——一个把手写 Nginx 变成 Web 表单的面板。用了一阵子，好感与警惕各占一半。

🐳 表单化的快乐

部署就是一个容器的事：

services:
  npm:
    image: jc21/nginx-proxy-manager:latest
    restart: unless-stopped
    ports:
      - "80:80"    # 证书验证
      - "443:443"  # HTTPS 入口
      - "81:81"    # 管理面板，建议改端口
    volumes:
      - ./data:/data
      - ./letsencrypt:/etc/letsencrypt

之后每加一个服务，就是在界面上添一条 Proxy Host：填个域名，指向内网目标，SSL 页签里一键申请 Let's Encrypt 证书——走 DNS Challenge 还能直接上通配符，子域名随便开。要给某个面板加道锁，Access List 点两下，Basic Auth 或 IP 白名单就有了。

以前半小时的活，现在两分钟。这份快乐是真的。

🐳 踩过的两个坑

快乐归快乐，坑也得记下来。

一个是容器网络：NPM 容器里写 localhost 指向的是它自己，不是宿主机。要么让它用 host 网络，要么目标老老实实填宿主机内网地址，第一次配的时候很容易在这转圈。

另一个更要命：证书续期是静默的。DNS Challenge 用的 API 密钥过期了，NPM 不会报错，它只是悄悄续不上，等某天浏览器弹出证书告警你才知道。所以证书剩余天数必须有个外部监控盯着，别信面板的岁月静好。

🐳 什么时候回到手写

用久了我也清楚它的边界在哪。

表单覆盖不了的规则——复杂的路径改写、流式代理这类——只能靠"自定义 Nginx 片段"往里缝，缝多了比手写还乱。更别扭的是可审计性：面板是黑盒，配置散落在数据库里，出了问题没法 diff，也没法进 git。

所以我的分界线是：常规的反代加证书，面板来，快；一旦规则复杂到需要注释才能看懂，或者配置重要到需要版本管理，就落回手写配置文件。两者并存，各干各的活。

💡 一点观察

可视化面板的本质是替你藏着复杂性，藏得越好越省心，也越晚让你发现问题。工具没有对错，关键是你得知道它什么时候开始替你做决定了。
