只监听 127.0.0.1 的网关

2026-11-09 · API 安全边界 · 约 2 分钟

给桌面应用加一个 OpenAI 兼容网关，让现成的工具直接用上它的模型。难点不是转发，是决定不做什么。

我的桌面应用里有很多账号和模型，而市面上现成的工具都讲 OpenAI 的协议。于是加了一个兼容网关：POST /v1/chat/completions 进来，转发到上游的对应接口，流式响应原样透传；GET /v1/models 列出可用账号。

🚪 三个安全决定

  1. 只监听 127.0.0.1:8787。局域网里其他设备碰不到它，连配置项都不给
  2. 账号用请求头选择（X-WB-Account，支持账号键或 uid 前缀），缺省用当前登录态。没有 token、没有密码——因为根本不暴露到网络
  3. 不做多账号轮询。把多个账号伪装成一个高配额端点去轮询，是这类工具的风控高发区。网关的价值是「让已有工具能用」，不是「伪装成共享池」

💡 边界即设计

做一个本地网关，最难的部分不是协议转换，是拒绝那些「顺手就能加」的功能。每一个没做的功能，都是一个不用承担的风险。

流式透传倒是意外的简单：上游的 SSE 分块原样写给客户端就行，不用重组——这也是选「透传」而不是「代理重写」的原因之一。
