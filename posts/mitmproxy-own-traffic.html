我用 mitmproxy 偷看自己的流量，看了才知道它在说什么

2026-11-25 · mitmproxy抓包 · 约 3 分钟

家里一个智能设备最近行为可疑：App 里明明关了某个功能，它好像还在偷偷联网。与其猜，不如把流量摊开看。

家里一个智能设备最近行为可疑：App 里明明关了某个功能，它好像还在偷偷联网。与其猜，不如把流量摊开看。

于是请出了 mitmproxy——一个中间人代理。原理说穿了很简单：HTTPS 之所以看不到内容，是因为流量加密；那就让代理变成你信任的「翻译」，两边各自加密，中间明文。

🪜 两步就能上手

上手门槛低得不像安全工具。

第一步，电脑上跑 mitmweb，它会开一个 8080 端口和一个网页界面；第二步，把要观察的设备 WiFi 代理指向这台电脑，再用设备浏览器访问 mitm.it 下载并信任它的 CA 证书。iOS 别忘了去「关于本机 → 证书信任设置」里手动打开那个开关，这一步漏了会以为工具坏了。

之后 HTTPS 流量就明文躺在界面里了。流量多的时候用过滤表达式，比如 ~u config 只看带关键词的请求，比在瀑布里捞针舒服太多。

mitmweb                      # 网页界面，默认 8080 端口
mitmdump -w run.dump         # 录制流量存档
mitmweb -S run.dump          # 离线回放，慢慢分析

🛠️ 改写比旁观的收获大

纯看流量已经很有信息量，但真正的收获来自改写。

写个小脚本挂上去，请求响应都能在回调里动手术。我常用它干一件事：把自家应用的某个配置接口返回改掉，看前端会怎么反应——后端没排上日的功能，前端可以先联调。

from mitmproxy import http

def response(flow: http.HTTPFlow):
    if flow.request.path == "/v1/config":
        data = json.loads(flow.response.text)
        data["new_feature"] = True
        flow.response.text = json.dumps(data)

那次排查智能设备，就是靠这个思路确认的：设备根本没请求我关掉的功能对应的接口，问题在 App 状态没刷新。十分钟，省掉一次毫无头绪的折腾。

🚧 边界画在哪

顺手要提一句技术上的坑：很多新版系统的 App 默认不信任用户装的证书，这是系统在收紧；遇到证书固定（Pinning）的应用，代理证书会直接被拒——那是应用在正当自卫。

我的原则跟着能力走：只抓自己的设备、自己的应用、自己有权限的服务。别人的流量，任何语境下都不该碰，工具中立不等于行为中立。

💡 一点观察

亲眼看一次自己设备的联网记录，感受会很微妙：原来后台有这么多我不知情的对话。看自己的流量是一种提醒——隐私不是设置里一个开关，而是要偶尔亲手验证的东西。
