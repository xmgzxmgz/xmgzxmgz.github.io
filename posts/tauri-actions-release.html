Tauri 应用的双平台自动发布

2026-11-11 · Rust TauriCI · 约 2 分钟

推一个 tag，macOS 的 dmg 和 Windows 的安装包、便携版自动挂到 Release。中间有两个坑值得记。

桌面应用的发布流程我全部放在 GitHub Actions 里：推一个 v* tag，macOS 出 dmg 和 app 包，Windows 出 NSIS 安装包加一个免安装的便携版 zip，全部自动挂到 Release 页。

⚙️ 结构

on: push tags 'v*'
  build-macos   (macos-latest, 60min): tauri-action --bundles dmg,app
  build-windows (windows-latest,45min): tauri-action --bundles nsis
                                        + Compress-Archive 打便携版

🕳️ 两个坑

坑一：便携版 zip 里的 exe 名字。Tauri 配置里的 productName 和 Cargo 的 package.name 是两回事——打包产物用的是后者。脚本里写死前者会直接 Get-Item 失败。注释里我特意写了一句「真实二进制名由 Cargo 决定」，因为这个问题我查过一次。

坑二：构建额度。macOS runner 按 10 倍计费。公开仓库的 Actions 免费所以无所谓，但要用官方托管镜像——公开仓库绝不能挂 self-hosted runner，陌生人的 PR 代码会在你自己的机器上执行。另外用 concurrency 组取消同 tag 的旧运行，避免重复烧额度。

💡 代价与收益

macOS 单次构建 40–60 分钟，Windows 30–45 分钟，两个 job 并行。换来的是：任何一台电脑上 git tag v0.x.y && git push --tags，几分钟后三个安装包就位。发布摩擦力降到接近零之后，发版频率明显变高了——这本身就是产品质量的一部分。
