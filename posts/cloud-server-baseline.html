新服务器开机的头十分钟，扫描器已经敲门了

2026-11-26 · 云服务器安全 · 约 2 分钟

一台新开的云服务器，从拿到公网 IP 到收到第一次扫描，往往只要几分钟。不夸张地说，加固的黄金窗口就是开机的头十分钟——晚一步，爆破日志已经刷屏了。

🐳 裸奔的代价

裸机的日常是这样的：认证日志里每天几百上千条 Failed password，全世界的扫描器在轮流试弱口令。如果端口开得多一点，还有更经典的剧本——某个缓存服务开着默认端口无密码裸奔，几小时内就被写进挖矿定时任务。

加固思路一句话就够了：不需要的服务不开，需要的服务收紧访问方式。

🐳 头十分钟清单

我现在的固定动作，按顺序来：

1. 密钥放好，新开窗口验证能登录
2. sshd 禁密码、禁 root 直接登录
3. 防火墙白名单只放必要端口
4. fail2ban：连错 5 次自动封 1 小时
5. 自动安全补丁 + 每周快照

性价比最高的是第 1、2 步。禁掉密码登录之后，那每天上千条爆破日志瞬间变成无害噪音——门都换成了锁，撬棍就没用了。改 SSH 端口也常被提起，它防的是扫描噪音，不是安全本质，属于可选项。

防火墙有个常见误解：以为云控制台配了就不用管系统内，或者反过来。正确答案是两层都要配且保持一致——控制台是实例前的第一道过滤，系统内的防火墙兜底，防止哪天误开一个端口就直接裸露。

🐳 顺序错了会把自己锁外面

这套清单里唯一会「伤到自己」的就是 SSH 那步，顺序千万不能反：先把密钥放好、开个新窗口验证能登录，再去改配置，最后 reload。反过来的下场是把自己锁在门外。

好在云厂商的控制台一般都有网页救援通道，锁死了还有救，但那体验谁试谁知道，不值得第二次。

最后别忘开监控告警，盯两个信号：CPU 突增、出流量突增。机器被入侵挖矿，最先喊疼的就是这两项。

💡 一点观察

安全大多时候是减法：少开一个端口、少留一种登录方式、少一个默认密码。暴露面每减一寸，半夜被告警吵醒的概率就小一分。
