eSIM 切卡的实现笔记

2026-09-18 · eSIM 协议 · 约 2 分钟

从 BER-TLV 到启用停用 Profile：与 lpac 逐字节对齐的三条指令、分帧规则，以及「9eSIM 读不出 EID」的真相。

CellPort 的核心功能是 eSIM/eUICC 的 Profile 管理。这篇记录实现时的关键结论，编码全部与开源的 lpac 对齐——逐字节一致是对这类实现的基本要求。

📖 读列表：BF2D

GetProfilesInfo 用 BF2D 00，响应按 BF2D → A0 → E3 三层解析，每个 Profile 的标签：5A ICCID、4F ISD-P AID、9F70 状态、90 昵称、91 运营商、92 Profile 名、95 类别。

🔁 切卡：BF31 / BF32

启用和停用分别是 BF31 / BF32，请求带 refreshFlag = FALSE。单激活卡上启用新 Profile 时，eUICC 会自动停用当前已启用的那个——这是卡的正常语义，不是 bug。对已停用的 Profile 再发停用会返回 Code=2（invalidProfile），同样正常。

写入后 modem 的 SIM 会话不会自动刷新，需要 AT+CFUN=1,1 重启模块才生效——程序要做的是引导、等待端口恢复、自动重连。

🗑️ 删除与昵称

删除是 BF33（无 A0 包装、无 refreshFlag）；昵称是 BF29，按 ICCID 定位而不是 AID，昵称限 64 个 ASCII 字符。

🕳️ EID 是个独立问题

SGP.22 的 BF3E 和 SGP.02 的 GET DATA 9F7F 两条路径，在 9eSIM 这类早期卡上都被拒（6A80 / 6D00）——是卡不提供，不是模块问题。EID 读不出和 Profile 管不了，是两条独立的路径，UI 上必须分开提示。
