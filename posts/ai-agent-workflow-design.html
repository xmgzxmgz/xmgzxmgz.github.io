Agent 的自主度，是个滑块不是开关

2026-11-26 · AI Agent工作流 · 约 3 分钟

总有人问我：Agent 到底该给它多大的自主权？

我现在的答案是，这个问题本身就问歪了。自主度不是开关，是个滑块，每一档都有明确的适用场景。

🐳 能写死就别放开

我踩过的第一个坑，是一上来就做全自动 Agent。

后来想明白了：步骤能数得清的活儿，根本不需要自主决策。比如早报流程，抓取、摘要、推送三步写死，模型只负责中间摘要那格填空。可靠性高，出了问题一眼能定位。

真正需要自主权的，是"调研这个课题再写份报告"这种路径没法预先枚举的任务。所以我的路线很实用主义：先写死流程跑通，再把变数最大的那一步交给模型。跑稳了，再交出下一步。可靠性和自主步数成反比，每多一步自由发挥，成功率就打一次折。

🐳 工具要小而钝

给了模型决策权，工具就是它的手脚。我给自己立了三条规矩：粒度小、语义清楚、返回可观察。"查询订单状态"就比"订单管理"好——前者模型不会猜错用途。工具描述把参数和返回写明白，返回值带结构化的错误信息，模型才有依据修正下一步。

核心循环其实短得惊人：

while not done:
    plan = llm(任务, 历史, 工具列表)   # 决策
    result = run(plan.tool, plan.args) # 调用
    历史.append(result)                # 观察
    if plan.risky:
        ask_human(plan)                # 闸门

复杂度不在循环里，在每一步失败之后怎么办。

🐳 失败要有台阶

这是我认为最值得花心思的部分，恢复路径我分三层设计：

可重试的错误（超时、限流），指数退避重试，上限三次。工具报错了，把错误原文喂回模型让它自我修正，最多两轮。还不行，就停下来，带着完整的上下文去找人。

别嫌这台阶矮。失控的 Agent 标准形态就是循环烧钱，所以我还加了预算：步数、token、时间，哪个上限先到就停。

删除、支付、对外发送这类高危动作，不管前面跑得多顺，都留一道人工确认的闸门。自动化省的时间，不该拿来替人担责任。

💡 一点观察

自主度本质上是信任预算，而信任要靠数据挣。我的做法是攒二十个真实任务当考卷，每次调滑块就跑一遍通过率。拨一格，验一次，比"感觉它变聪明了"踏实得多。
