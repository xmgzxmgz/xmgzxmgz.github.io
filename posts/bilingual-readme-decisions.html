双语 README 的三个决定

2026-09-26 · 开源 写作 · 约 2 分钟

两个项目都做了中英双语 README。做下来发现真正要决定的只有三件事：谁在前、翻译到什么程度、谁来维护同步。

我开源的项目里，两个做了双语 README（中文 + English）。做下来发现，双语化真正的难点不是翻译，是三个结构性的决定。

1️⃣ 谁在前

决定因素是目标受众在哪。面向国内场景的工具（软考、国产硬件）中文为主；有国际受众的（罗技外设、eSIM 管理）在中文主文档顶部加一段英文导语和切换链接——让英文读者三秒内知道这是什么，再决定要不要点进去。

2️⃣ 翻译到什么程度

不是所有内容都值得双份。我的分层：首屏（是什么、为什么、快速开始）必须双语；深度技术细节跟主语言——一个只想快速评估项目的英文读者不需要知道 APDU 的字节布局。翻译一半留一半，是诚实的成本控制，不是偷懒。

⚠️ 一条红线

两个文件必须同步更新。双语 README 最伤信誉的死法是：中文版更新到 v3，英文版停在 v1——英文读者会认为项目不活跃。维护不动就别开双语，开了就当两个文件养。

双语 README 的本质是承认「不同读者需要不同深度的入口」，然后用结构去实现这个承认。
