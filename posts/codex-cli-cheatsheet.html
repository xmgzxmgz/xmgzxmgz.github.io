终端里的 AI 编码工具，怎么用才不像玩具

2026-11-26 · AI 编码命令行 · 约 2 分钟

不少朋友装了终端里的 AI 编码工具，试了两把就闲置了。

问题多半不在工具，在用法。把它当"终端里的结对程序员"来用，感觉完全不一样——这类工具（比如 Codex CLI）的心智模型其实就这一句话。

🐳 审批是个滑块

这类工具一般有三档审批模式：只读建议、自动编辑、全自动。

我的分配是：陌生代码库用只读，让它先出分析和建议，执行前逐个确认；日常开发用自动编辑当主力档，改文件自动，跑命令还是要我点头；全自动只在有兜底的时候开——git 干净、随时可回滚，敏感文件不在工作区里。

听着耳熟？对的，自主度是滑块不是开关，Agent 工作流是这个道理，终端工具也是同一个道理。

🐳 约定写进仓库

效率提升最明显的一招，是在仓库根目录放一个约定文件（Codex CLI 是 AGENTS.md），每次会话自动注入。

写"希望每次都被遵守的事"：

# 项目约定
- 构建：npm run build，改完必跑测试
- 技术栈：Vite + React + TS
- 不要动 src/legacy/ 目录
- 提交信息格式：类型: 摘要

构建命令、代码规范、禁区，全写进去。它随仓库走，团队共享，是项目契约而不是个人偏好。省掉的是每开一个会话都要重新交代一遍的成本。

🐳 先要计划再动手

大需求我永远先说一句："先给我实现计划，别动代码。"确认了计划，再让它按第一步执行。分步推进，每步可验收，比一口气全自动赌一把靠谱得多。

供给上下文也是门手艺：直接贴报错全文加相关文件路径，减少它自己摸索的轮次；截图可以直接粘进去。改完让它自己跑测试、贴输出——声称完成和测试通过，是两回事。

进阶玩法是挂 MCP 扩展，让它能驱动浏览器、查数据库。但只挂来源可信的，生产凭据永远不进开发机的配置。

💡 一点观察

工具像不像玩具，取决于你给它定了多大的验收标准。会话断了用 resume 接着聊，改完 diff 审一遍再提交——把"验收"做成习惯，生产力是验收的副产品。
