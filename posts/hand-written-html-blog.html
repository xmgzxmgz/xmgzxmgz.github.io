为什么手写 HTML 不用生成器

2026-11-10 · 博客 极简 · 约 2 分钟

这个博客没有构建步骤、没有框架、字体是系统自带的。发一篇文章要改三个文件——这是成本，也是特性。

你现在看的这个博客，是手写的 HTML + CSS。没有 Jekyll、Hugo、Astro，没有构建步骤，字体用系统自带的。git push 之后 GitHub Pages 直接吐静态文件，结束。

⚖️ 诚实的成本清单

发一篇文章要动三个地方：生成文章页、往首页列表插一张卡片、往 sitemap 加一条。改版式要同时改多个文件。分类筛选是自己写的十几行 JS。这些用任何生成器都能省掉。

🎯 换来的东西

  • 零依赖零构建：三年后 clone 下来双击就能看，不用先装 400 个 npm 包
  • 关掉 JS 也能读：所有内容直接写在 HTML 里，搜索引擎原样抓取
  • 可完全控制：meta、结构、语义标签，都是我写的，没有模板的黑盒
  • 改起来没有心理负担：没有「升级依赖把构建搞坏」这种事

💡 这不是给所有人的建议

如果你要标签、归档、RSS、评论、全文搜索——用生成器，别折磨自己。我的需求恰好是「几十篇文章、重内容轻功能」，手写的总成本才更低。

工具选型的标准不是「哪个更先进」，是「哪个的维护成本和我的使用频率匹配」。
